# Agent subscriptions

In the native Agents window, open **Agent Subscriptions** from the title bar, account menu, or Command Palette. The command uses the existing keyboard-accessible Quick Pick. It is hidden in the browser preview, which cannot launch local clients.

| Provider | Connection | Where you work |
| --- | --- | --- |
| Codex | Enables the existing native Codex provider and starts its ChatGPT account sign-in when needed. An already signed-in account is reused. | Native agent picker and chat. |
| Anthropic | Opens the unmodified official Claude Code executable. **Sign in** runs `claude auth login`; **Open Claude Code** uses the client's saved account. | Editor terminal in the focused session's local working directory. |
| Devin Subscription | Opens the Devin browser account sign-in with a loopback callback and PKCE. The authentication provider stores the returned session in VS Code SecretStorage and connects it to the local native agent host. | Native agent picker, model catalog, and chat using the official Devin executable's ACP transport. |
| Devin CLI | Opens the official Devin CLI. **Sign in** runs `devin auth login`; **Open Devin CLI** uses the client's saved account. | Editor terminal in the focused session's local working directory. |

Executable paths are machine-scoped settings: `agents.subscriptions.claudeExecutable` and `agents.subscriptions.devinExecutable`. Defaults are `claude` and `devin` on PATH. These fields accept an executable path, with arguments passed separately. A virtual workspace is rejected before starting a local client. Without a session working directory, the action uses the editor's first local workspace folder.

Codex, Claude Code, and Devin CLI authentication and credential storage stay with their official clients. The separate Devin Subscription authentication extension opens the provider's own browser page, validates a one-use loopback callback state, exchanges the code over HTTPS with PKCE, and stores the returned token in the editor's SecretStorage. It does not read or write Devin CLI's credentials. A saved browser account does not prove subscription entitlement or a completed model turn. Terminal launch clears the Claude API key/auth token environment overrides, or Devin's `WINDSURF_API_KEY`, for this process only. Other client configuration and organizational controls still apply; the official client determines account entitlement and billing. Codex enablement respects managed policy. The isolated development launcher gives Codex and Claude separate configuration homes; Devin CLI uses its own existing credential store.

Claude subscriptions are hosted through the official Claude Code client because Anthropic distinguishes that usage from third-party Agent SDK authentication. No custom Claude OAuth implementation is added. The Devin Subscription browser endpoints match both the current source and installed backend of SimpleRAG (`GUI/subscription_providers.py`); SimpleRAG's inference still uses the CLI/ACP bridge. Its account connection is not evidence of a CLI-independent chat API. The extension rejects callbacks with absent/mismatched state and does not import SimpleRAG's auto-approval behavior.

The native Devin adapter uses the saved browser session through a child-process-only `WINDSURF_API_KEY` value with the official client's `devin-session-token$` prefix. It does not change the CLI's saved login or place credentials in arguments, URLs, or logs. The local agent host registers the provider when the configured executable can be found. The account bridge forwards credentials only to the registered Devin provider with the expected protected resource, reuses the saved account after host restart, and withdraws it on sign-out. The catalog is real CLI metadata; visibility of a model does not prove account entitlement. Each chat owns its ACP process, streams responses and tool progress, restores its own session through `session/load`, and routes permission decisions through the host. It never selects an always-allow permission automatically.

Restoration reads the exact chat's saved provider data for metadata before creating its in-memory record. This preserves its local working directory, model, creation time, and latest activity time without starting a client for a passive metadata lookup. Older saved records without an activity timestamp remain readable. A failed replay restores the last successfully loaded transcript so a retry starts cleanly. The native session restores its own model and separate Thinking/Speed selectors; catalog variant ids are not blindly sent as model-family selector values during restore. An unchanged host model selection is a no-op, including when the host normalizes absent config to an empty object. Actual model changes after release first reopen the existing native session.

Explicit model changes resolve the selected catalog variant to an advertised model choice and apply its Thinking and Speed values using the fresh configuration returned after each request. Grouped model choices are supported. Long-context and legacy thinking model ids remain distinct, and Fusion keeps the sidekick's reasoning choice while Speed may accelerate both models. Unknown or ambiguous mappings are rejected before mutation. Every applied value and the final combined configuration must be confirmed by the client. A failed change attempts to restore the previous model and dependent settings without changing permission modes. If the connection drops or rollback cannot be confirmed, the backing records that reconciliation is needed; another turn is blocked until the settings are reconciled. Selecting an available model can recover even when the previous model has disappeared from the catalog.

Outgoing prompts preserve automatic simple context, inline text from unsaved editors, resource references, selections, and read-only snapshot hints. Embedded images and binary documents require the corresponding prompt capabilities advertised during ACP initialization. Unsupported context produces an attachment-specific error rather than rejecting every message that carries workspace context. The transport drains stderr without displaying raw output and rejects malformed protocol messages. Client filesystem and terminal RPC capabilities are not advertised; the official agent owns its tools.

Tool rows retain their inputs and latest reported content when a completion update omits those fields. Text, images, embedded resources, and reported diffs are mapped to result content; references are not fetched and reported diffs are not applied by the mapper. Raw output is used when the agent supplies no renderable content, and later raw-output updates replace the previous raw result. Explicit approvals remain marked as user actions in the provider's current history. Denials and cancelled approvals remain terminal, so late tool updates cannot revive them. A changed input cancels a pending permission rather than accepting a stale approval; JSON object key ordering alone does not count as a change. Repeated permission requests settle the superseded RPC and require a decision for the replacement. An ordinary approval never selects an always-allow option. Failed or aborted turns finalize unfinished tools while retaining available partial output. These mappings follow the [ACP tool-call update contract](https://agentclientprotocol.com/protocol/v1/tool-calls).

On November 16, 2026, Devin's public browser route and continuation assets confirmed the loopback address format and the return of `code` with the original `state`. An unauthenticated empty JSON request to the real token endpoint returned HTTP 422 naming `code` and `code_verifier` as required body fields. The installed official CLI's embedded exchange-response type identifies `session_token`. The extension now sends only the code and verifier and accepts that response field, without a borrowed OAuth client id or guesses at unrelated token fields. These checks validate the transport contract without signing into an account; they do not prove live account authorization or entitlement.

Each successful browser sign-in gets a fresh local account identity because the exchange response does not establish a stable user identity. This prevents a different account from inheriting the old account's extension grants. Credential mutations are serialized. Cancellation during a write restores the previous stored session before a queued sign-out runs, and no cancelled session is announced as connected.

Validation: focused tests cover Codex enable/sign-in ordering, reuse of an authenticated account, managed-policy rejection, both launch actions for both CLI providers, executable paths and working directories containing spaces, credential environment overrides, terminal activation, rejection of virtual folders, and dispatch to the separate browser account connection. Extension tests cover PKCE, exact callback-state matching, cancellation, timeout, HTTP errors, token validation, SecretStorage persistence/removal, and concurrent sign-in. Native adapter tests cover protocol request correlation, malformed input, process framing, selected-model launch, turn routing, permission decisions, session restoration, greeting messages with automatic context, and attachment capability handling. Browser bridge tests cover account reuse, host registration checks, sign-out, and reconnect. A real installed-client probe loaded 1,073 catalog variants and negotiated ACP version 1 with a deliberately invalid token, without sending a model turn. This proves transport compatibility and catalog parsing, not account authorization or entitlement.

Live desktop verification on November 16, 2026: a fresh native Devin Subscription chat using SWE-2 Max sent `hey` with the workspace's automatic context. Devin completed a visible response identifying itself and the `D:\vscode` workspace. After restarting the local agent host, the same native conversation retained SWE-2 Max and completed the follow-up `What was my previous message? Reply briefly without running tools or changing files.` with `Your previous message was "hey".` The same conversation then switched from SWE-2 Max to SWE-2 High and back to Max, with a completed response after each switch. It was left on SWE-2 Max. These checks verify the saved subscription account, context serialization, provider-backed responses, conversation context after host restart, and live reasoning-variant changes. Real tool approval and live turns across the other model families or fast variants remain separately unverified; they have focused adapter coverage.

An offline catalog probe resolved all 1,073 installed-client catalog variants to the captured real session's advertised model choices, with no cross-family matches and no model turns requested. This validates base-selector mapping, including accelerated Fusion pairings; it does not establish entitlement to every model or exercise every family's dependent selectors against the live service.

A live read-only check used Devin's file-reading tool to read the first 12 lines of `D:\vscode\README.md` and returned its heading. That check preceded the tool-state retention changes. Desktop automation was stopped by the user with Escape before the updated tool details could be reloaded and inspected. The updated mapper has focused adapter tests and a real chat-reducer assertion for cancelled permissions; live approval, cancellation, and result-detail verification of this increment remain outstanding. No editor-profile settings were changed for this increment.

Sixteen authentication-extension tests, 90 focused browser tests, and 50 native adapter test-run checks passed. The extension and client type checks, targeted lint, and layer checks passed. A native extension-host smoke test, run in a separate empty profile with a different development extension as its runner, discovered this provider as a built-in extension, activated it, and resolved a silent authentication lookup without starting a browser or CLI.
