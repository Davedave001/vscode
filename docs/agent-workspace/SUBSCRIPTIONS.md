# Agent subscriptions

In the native Agents window, open **Agent Subscriptions** from the title bar, account menu, or Command Palette. The command uses the existing keyboard-accessible Quick Pick. It is hidden in the browser preview, which cannot launch local clients.

| Provider | Connection | Where you work |
| --- | --- | --- |
| Codex | Enables the existing native Codex provider and starts its ChatGPT account sign-in when needed. An already signed-in account is reused. | Native agent picker and chat. |
| Anthropic | Opens the unmodified official Claude Code executable. **Sign in** runs `claude auth login`; **Open Claude Code** uses the client's saved account. | Editor terminal in the focused session's local working directory. |
| Devin Subscription | Opens the Devin browser account sign-in with a loopback callback and PKCE. The authentication provider stores the returned session in VS Code SecretStorage. | Separate account connection; native chat integration is still in development. |
| Devin CLI | Opens the official Devin CLI. **Sign in** runs `devin auth login`; **Open Devin CLI** uses the client's saved account. | Editor terminal in the focused session's local working directory. |

Executable paths are machine-scoped settings: `agents.subscriptions.claudeExecutable` and `agents.subscriptions.devinExecutable`. Defaults are `claude` and `devin` on PATH. These fields accept an executable path, with arguments passed separately. A virtual workspace is rejected before starting a local client. Without a session working directory, the action uses the editor's first local workspace folder.

Codex, Claude Code, and Devin CLI authentication and credential storage stay with their official clients. The separate Devin Subscription authentication extension opens the provider's own browser page, validates a one-use loopback callback state, exchanges the code over HTTPS with PKCE, and stores the returned token in the editor's SecretStorage. It does not read or write Devin CLI's credentials. A saved browser account does not prove subscription entitlement or a completed model turn. Terminal launch clears the Claude API key/auth token environment overrides, or Devin's `WINDSURF_API_KEY`, for this process only. Other client configuration and organizational controls still apply; the official client determines account entitlement and billing. Codex enablement respects managed policy. The isolated development launcher gives Codex and Claude separate configuration homes; Devin CLI uses its own existing credential store.

Claude subscriptions are hosted through the official Claude Code client because Anthropic distinguishes that usage from third-party Agent SDK authentication. No custom Claude OAuth implementation is added. Devin's native ACP chat adapter is not implemented by this change. The Devin Subscription browser endpoints and public client id match both the current source and installed backend of SimpleRAG (`GUI/subscription_providers.py`); SimpleRAG's inference still uses the CLI/ACP bridge. Its account connection is not evidence of a CLI-independent chat API. The new extension deliberately rejects callbacks with absent/mismatched state, accepts only concrete token fields, and does not import SimpleRAG's auto-approval behavior.

Official references: [Codex authentication](https://developers.openai.com/codex/auth), [Claude authentication](https://code.claude.com/docs/en/authentication), [Claude credential and embedding policy](https://code.claude.com/docs/en/legal-and-compliance), [Devin commands and ACP](https://docs.devin.ai/cli/reference/commands).

Validation: focused tests cover Codex enable/sign-in ordering, reuse of an authenticated account, managed-policy rejection, both launch actions for both CLI providers, executable paths and working directories containing spaces, credential environment overrides, terminal activation, rejection of virtual folders, and dispatch to the separate browser authentication provider. Extension tests cover PKCE, exact callback-state matching, cancellation, timeout, HTTP errors, token validation, SecretStorage persistence/removal, and concurrent sign-in. These tests use a simulated provider response; successful live Devin browser token exchange and a completed provider-backed model turn have not been verified.

Thirteen authentication-extension tests and 87 focused browser tests passed. The extension and client type checks, targeted lint, and layer checks passed. A native extension-host smoke test, run in a separate empty profile with a different development extension as its runner, discovered this provider as a built-in extension, activated it, and resolved a silent authentication lookup without starting a browser or CLI. The client and built-in extension compilation completed. The top-level full build failed in the separate Copilot build because its loaded `runtime.node` could not be unlinked (`EPERM`); the running user editor was preserved.

Manual test: open **Agent Subscriptions → Devin Subscription**, finish signing in on Devin's browser page, and confirm the editor reports the account connection only after the callback and token exchange succeed. Confirm **Devin CLI** remains a separate menu item that opens the installed client. The browser account can be signed out through the editor's Accounts menu.
