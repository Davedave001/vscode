# Agents and IDE mode switch

The title bar now offers a persistent, labelled Agents / IDE switch. Agents highlights the orchestration view; IDE highlights the code editor. The switch uses the existing workspace-aware actions, so folder, remote-host, chat-session, and draft handoff rules remain owned by the existing implementation.

Handoff uses the focused chat, including a nested chat with its own workspace. An explicitly clicked chat takes precedence over focus. The browser route passes that chat's identity with its folder instead of combining a nested workspace with the parent session. Browser and native routes share the materialized-session check: an unsent draft's folder may open in the IDE, while its provisional conversation stays owned by the Agents composer.

Browser-to-editor handoff preserves a local file URI's network server as part of the editor protocol path. A workspace such as `file://fileserver/shared projects/project` opens the same UNC share rather than a local `/shared projects/project` path. Regression checks serialize and parse the link, then reconstruct the file URI using the native protocol handler's `URI.file(uri.fsPath)` conversion; spaces, percent signs, fragment/query delimiters, and Unicode in folder names remain file-path content. Created chats retain their own conversation identity; unsent drafts still hand off only the folder.

In the Agents Window the control appears at the start of the title bar, before sidebar navigation. The native IDE's existing return-to-Agents title-bar action uses the same control. The setting `workbench.titleBar.workspaceModeSwitch` defaults to true; setting it to false and reloading restores the existing icon-style controls.

The control exposes a single keyboard focus target and a switch role with IDE mode on/off state. Click, Enter, and Space activate the existing action. Disabled actions remain disabled and cannot execute. Theme colors, spacing, radii, and focus outlines use existing tokens. The Agents accessibility help documents the control.

While the title-bar handoff action is pending, the control exposes busy and disabled states and ignores repeated click, Enter, and Space activation. Its current mode and focus do not change merely because the action started. Completion or failure restores availability according to the underlying command's latest enabled state, without changing that command's enabled flag. Errors still flow through the toolbar action runner. This guard is local to the title-bar control; command-palette and global shortcut invocations retain their existing behavior.

The native window service already looks for a window with the requested folder or workspace before creating a new one, and the native host sends the chat handoff to the single selected window. The action's `forceNewWindow` option protects against replacing the Agents window and does not by itself bypass matching-window reuse. This is source-level evidence; repeated native switches with unsaved buffers still need live verification.

For a multi-folder handoff, workspace consolidation now checks currently open, non-development editor workspaces before consulting previous-session state or creating an untitled workspace. Matching uses the complete unique folder set on the same remote authority, independent of folder order, and excludes transient or unresolved workspaces. The lookup returns the validated workspace identity with its window; after the asynchronous boundary, the caller checks that the window is still open on that identity and host. Both live matching and the previous-session fallback use the same folder comparison, so duplicate roots cannot masquerade as a different requested folder set. Remote folder path casing remains significant, while local file paths retain this platform's existing comparison rules. Returning an existing workspace identity lets the normal native open path reuse its window rather than create another workspace for the same folders. Main-process changes require relaunching Signal-C before a visible smoke test.

Press Ctrl+K followed by Ctrl+Shift+A to switch modes on Windows or Linux; on macOS use Cmd+K followed by Cmd+Shift+A. The shortcut invokes the existing session-workspace action from Agents and the existing current-workspace action from the native IDE. Existing Ctrl+Shift+A commands remain unchanged. The Agents command is also discoverable as Open in Editor in the command palette. Its default shortcut is inactive on phone layouts, while the welcome overlay is visible, and outside Agents windows. The tooltip and accessible description follow later shortcut remapping or removal. The browser preview IDE registers the same chord and a Switch to Agents command-palette entry for its embedder command.

## Browser preview

Start the existing server with `--workspace-preview` to enable the development preview shell:

```powershell
node scripts/code-sessions-web.js --mock --workspace-preview --skip-welcome --no-open --host 127.0.0.1 --port 8096
```

The ordinary server and E2E routes retain their existing behavior when this flag is absent. With the flag enabled, Agents and the real web IDE run in separate same-origin frames. Only the initially requested workbench starts immediately; the other loads on its first use. This also applies to a direct `?mode=ide` load or reload, avoiding simultaneous cold startup of both full workbenches. After their first use, switching only hides or reveals the retained frames, preserving their in-page conversations and unsaved buffers. Reloading or closing the browser page still follows the underlying workbenches' persistence behavior.

The Agents title-bar action invokes the preview host instead of an installed editor protocol. The IDE provides a return control at the top-left. Host messages are accepted only from the known workbench frames and the exact local origin. The mock Sessions factory now honors and disposes embedder command registrations, matching the production factory's command contract.

With both `--mock` and `--workspace-preview`, the two workbenches register the same browser-backed `mock-fs://mock-repo/mock-repo` sample workspace before workspace services initialize. The four sample files are seeded once in an IndexedDB transaction. Saved edits survive reopening; intentionally deleted files are not recreated. Cross-window file notifications invalidate the receiving provider's cached directory metadata, so later directory and file-size queries see committed peer changes. The ordinary mock E2E entry keeps its existing in-memory provider.

This is a local demo and does not establish access to an agent's desktop filesystem. The IDE opens the shared sample folder. The existing Agents mock picker selects a GitHub-shaped Cloud session workspace; the preview registers a read-only repository view that maps precisely that sample repository to the same saved files, without calling GitHub for its file contents. Other repository paths, authorities, and queries cannot use this mapping. Normal Agents windows continue to register the existing GitHub API filesystem when no embedder provider exists. Native workspace handoff uses the existing desktop action, independently of the preview shell.

### Repeatable preview smoke check

Start an updated mock preview server on an available loopback port, for example:

```powershell
node scripts/code-sessions-web.js --mock --workspace-preview --skip-welcome --no-open --host 127.0.0.1 --port 8099
```

In another terminal, run:

```powershell
node scripts/test-agent-workspace-preview.mts http://127.0.0.1:8099/
```

The check uses a fresh headless browser context, installed Edge on Windows or Playwright Chromium elsewhere, and the mock provider. It blocks external HTTP requests and operates on the browser-only sample workspace. It completes a mock conversation, retains a follow-up draft and an explicitly dirty untitled buffer across mode switches, edits and saves README.md, reloads the IDE, and opens the deferred Agents workbench. A report and screenshots are saved in `.build/agent-workspace-preview-smoke/<run>/`; failures retain their stage, report, and screenshot. Request interception disables the browser HTTP cache, so reload also exercises cold module loading. The script does not launch an installed editor, reuse a browser profile, or verify real provider authentication.
