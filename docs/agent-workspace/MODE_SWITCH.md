# Agents and IDE mode switch

The title bar now offers a persistent, labelled Agents / IDE switch. Agents highlights the orchestration view; IDE highlights the code editor. The switch uses the existing workspace-aware actions, so folder, remote-host, chat-session, and draft handoff rules remain owned by the existing implementation.

Handoff uses the focused chat, including a nested chat with its own workspace. An explicitly clicked chat takes precedence over focus. The browser route passes that chat's identity with its folder instead of combining a nested workspace with the parent session. Browser and native routes share the materialized-session check: an unsent draft's folder may open in the IDE, while its provisional conversation stays owned by the Agents composer.

The selected chat must also have been sent at least once. A created parent session does not make a new nested chat ready to transfer. Both handoff routes omit the provisional chat identity while keeping its workspace selection; after the chat's status leaves Untitled, active, waiting, completed, and failed conversations retain their normal editor handoff.

Browser-to-editor handoff preserves a local file URI's network server as part of the editor protocol path. A workspace such as `file://fileserver/shared projects/project` opens the same UNC share rather than a local `/shared projects/project` path. Regression checks serialize and parse the link, then reconstruct the file URI using the native protocol handler's `URI.file(uri.fsPath)` conversion; spaces, percent signs, fragment/query delimiters, and Unicode in folder names remain file-path content. Created chats retain their own conversation identity; unsent drafts still hand off only the folder.

In the Agents Window the control appears at the start of the title bar, before sidebar navigation. The native IDE's existing return-to-Agents title-bar action uses the same control. The setting `workbench.titleBar.workspaceModeSwitch` defaults to true; setting it to false and reloading restores the existing icon-style controls.

The control exposes a single keyboard focus target and a switch role with IDE mode on/off state. Click, Enter, and Space activate the existing action. Disabled actions remain disabled and cannot execute. Theme colors, spacing, radii, and focus outlines use existing tokens. The Agents accessibility help documents the control.

While the title-bar handoff action is pending, the control exposes busy and disabled states and ignores repeated click, Enter, and Space activation. Its current mode and focus do not change merely because the action started. Completion or failure restores availability according to the underlying command's latest enabled state, without changing that command's enabled flag. Errors still flow through the toolbar action runner. This guard is local to the title-bar control; command-palette and global shortcut invocations retain their existing behavior.

The native window service looks for a window with the requested folder or workspace before creating a new one, and the native host sends the chat handoff to the single selected window. The action's `forceNewWindow` option protects against replacing the Agents window and does not by itself bypass matching-window reuse.

Native Agents-to-IDE handoff explicitly permits reuse of an open multi-root workspace when the requested folder is one of its roots on the same remote authority. An exact single-folder window keeps priority; otherwise the most recently focused matching multi-root editor is preferred. Nested directories do not count as roots. This preference applies only to the handoff, leaving ordinary Open Folder behavior unchanged. It consults open, non-development, non-transient workspaces with resolvable workspace files; it does not infer a live folder inventory from a missing workspace file or expand a containing match from previous-session state.

Without a selected folder, the native mode handoff requests reuse of the most recently focused ordinary editor on the exact same remote authority, including an editor that already has a workspace or unsaved buffers. Local handoff explicitly selects the local host. Agents windows, extension-development windows, and windows whose configuration is not yet known are excluded. If no suitable editor exists, a new empty editor is created. The preference does not apply to ordinary New Window requests and does not override an explicit profile, temporary profile, or force-reuse request.

For a sent, folderless chat, the native action also supplies its editor-compatible conversation identity. The native host queues the existing chat-open IPC message only for the selected editor, whether it creates or reuses that window. Ordinary ambiguous requests do not dispatch a conversation. Unsent drafts supply no identity. Shared remote hosts keep the mapped chat identity and target authority; unsupported remotes and differing host ownership omit the identity and show a chat-specific explanation. Focused action and dispatch tests cover these rules. The native conversation smoke check also verifies the rendered handoff through the real native SDK and a loopback mock model.

The browser's folderless handoff uses the product's dedicated `signal-c://editor-window/open` route, with optional `session` and `remoteAuthority` query parameters. All editor handoff links use the product's configured protocol, including stable, insider, and exploration builds, rather than selecting an installed Microsoft editor from the quality label. A sent chat retains its mapped conversation identity; an unsent chat only opens or focuses the editor. A remote authority selects the matching host without inventing a folder path. The native receiver supports both an already running application and first-window startup, uses the same empty-editor reuse and chat-dispatch helpers as the native action, and consumes a startup link once. Folder-backed links retain their existing route.

Windows protocol registration preserves resolved `--user-data-dir`, `--extensions-dir`, and `--shared-data-dir` overrides when they were explicitly supplied at launch. This lets a browser-triggered process find the same editor storage and IPC endpoint as the development launcher. Electron receives raw argument values and applies Windows quoting itself; manually quoted app roots would become literal quote-bearing arguments. Startup modes, test flags, old URLs, and other process arguments are excluded from the registered command. Portable mode retains its existing registration skip.

At cold startup, hot-exit backups may open alongside the requested editor. They remain eligible for normal recovery; the explicit folderless handoff chooses one ordinary editor on the requested host using the existing most-recently-focused window rule. It never broadcasts the conversation to all recovered windows, chooses a different host, or suppresses unsaved-buffer recovery just to obtain one window.

The dedicated receiver rejects other schemes, authorities, paths, fragments, duplicate or unknown query parameters, malformed chat identities, and invalid or oversized remote authorities. Local and remote destinations follow the existing external-protocol confirmation preferences; declining does not open the requested editor or change those preferences. Accepted requests use the existing registered chat provider to restore the conversation. The link does not carry account credentials or run commands.

Browser handoff of a multi-root workspace uses the same dedicated route with a `folders` query parameter containing every selected chat working-directory URI. The receiver opens that list through the normal native workspace consolidation, exact-folder-set reuse, and chat-target selection. Single-root links retain their existing path route. Root lists contain absolute local file URIs, including UNC shares, or remote URIs belonging to the requested resolver. Mixed hosts, non-folder schemes, query/fragment-bearing roots, malformed lists, more than 100 roots, individual URIs longer than 8192 characters, and serialized lists larger than 65536 characters are rejected. An unsupported root prevents the browser from opening only the supported subset. URI serialization may lowercase a resolver authority; parsing restores the requested authority's original casing without changing folder path casing.

An explicit chat open also takes priority over late startup agent discovery. While that chat is loading, the view may temporarily have no model; this empty interval must not trigger a default-session restore that later replaces the requested conversation. Ordinary startup discovery still initializes an idle view. The transition tests reproduce the competing restoration before the guard and verify both explicit navigation and idle restoration.

For a multi-folder handoff, workspace consolidation now checks currently open, non-development editor workspaces before consulting previous-session state or creating an untitled workspace. Matching uses the complete unique folder set on the same remote authority, independent of folder order, and excludes transient or unresolved workspaces. The lookup returns the validated workspace identity with its window; after the asynchronous boundary, the caller checks that the window is still open on that identity and host. Both live matching and the previous-session fallback use the same folder comparison, so duplicate roots cannot masquerade as a different requested folder set. Remote folder path casing remains significant, while local file paths retain this platform's existing comparison rules. Returning an existing workspace identity lets the normal native open path reuse its window rather than create another workspace for the same folders. Main-process changes require relaunching Signal-C before a visible smoke test.

The repeatable Windows check `node scripts/test-agent-workspace-native.mts` launches the prepared native development runtime in a fresh fixture profile with hidden windows, two Git roots, in-memory secret storage, disabled subscription providers, and a local mock endpoint. It creates an unsaved IDE buffer and an Agents draft, then performs two round trips using the real mode controls. It asserts unchanged native window IDs, retained roots and dirty buffer, retained draft, and hidden windows at every recorded stage. Captures and `report.json` are stored under `.build/agent-workspace-native-smoke/`. The verified run `2026-11-17T11-09-05-230Z-69460` passed with zero model requests. This proves native context retention in that fixture; it does not prove visible OS focus, real provider sign-in, or a packaged installation.

Pass `--empty-workspace` to start from Agents without a selected folder. This creates the first empty editor, adds an unsaved buffer, and checks two further round trips retain that same editor and the folderless Agents draft. The pre-fix fixture opened a third native window on the first return; run `2026-11-17T11-24-40-214Z-17864` passed after the fix, with both original window IDs and zero model requests.

Pass `--conversation` to exercise a sent, folderless conversation. This variant registers a deterministic mock response, waits for the native SDK to discover its mock catalog, selects the explicit GPT-5.3-Codex mock model through the composer picker, and sends one prompt. It verifies the rendered response in both windows, a follow-up draft, a dirty IDE buffer, repeated window reuse, and no additional model requests during restoration. The fixture uses synthetic credentials and its own profile; real subscription sign-in, entitlement, and Auto routing remain outside this check. Composer-scoped model selectors exclude the off-screen accessibility announcement. The local `/models` response supplies both the chat catalog's `data` array and an empty editor proxy `models` array.

Press Ctrl+K followed by Ctrl+Shift+A to switch modes on Windows or Linux; on macOS use Cmd+K followed by Cmd+Shift+A. The shortcut invokes the existing session-workspace action from Agents and the existing current-workspace action from the native IDE. Existing Ctrl+Shift+A commands remain unchanged. The Agents command is also discoverable as Open in Editor in the command palette. Its default shortcut is inactive on phone layouts, while the welcome overlay is visible, and outside Agents windows. The tooltip and accessible description follow later shortcut remapping or removal. The browser preview IDE registers the same chord and a Switch to Agents command-palette entry for its embedder command.

## Browser preview

Start the existing server with `--workspace-preview` to enable the development preview shell:

```powershell
node scripts/code-sessions-web.js --mock --workspace-preview --skip-welcome --no-open --host 127.0.0.1 --port 8096
```

The ordinary server and E2E routes retain their existing behavior when this flag is absent. With the flag enabled, Agents and the real web IDE run in separate same-origin frames. Only the initially requested workbench starts immediately; the other loads on its first use. This also applies to a direct `?mode=ide` load or reload, avoiding simultaneous cold startup of both full workbenches. After their first use, switching only hides or reveals the retained frames, preserving their in-page conversations and unsaved buffers. Reloading or closing the browser page still follows the underlying workbenches' persistence behavior.

The Agents title-bar action invokes the preview host instead of an installed editor protocol. The IDE provides a return control at the top-left. Host messages are accepted only from the known workbench frames and the exact local origin. The mock Sessions factory now honors and disposes embedder command registrations, matching the production factory's command contract.

With both `--mock` and `--workspace-preview`, the two workbenches register the same browser-backed `mock-fs://mock-repo/mock-repo` sample workspace before workspace services initialize. The four sample files are seeded once in an IndexedDB transaction. Saved edits survive reopening; intentionally deleted files are not recreated. Cross-window file notifications invalidate the receiving provider's cached directory metadata, so later directory and file-size queries see committed peer changes. The ordinary mock E2E entry keeps its existing in-memory provider.

This is a local demo and does not establish access to an agent's desktop filesystem. The IDE opens the shared sample folder. The existing Agents mock picker selects a GitHub-shaped Cloud session workspace; the preview registers a read-only repository view that maps precisely that sample repository to the same saved files, without calling GitHub for its file contents. Other repository paths, authorities, and queries cannot use this mapping. Normal Agents windows continue to register the existing GitHub API filesystem when no embedder provider exists. Native workspace handoff uses the existing desktop action, independently of the preview shell.

### Repeatable preview smoke check

Start an updated mock preview server on an available loopback port, for example:

```powershell
node scripts/code-sessions-web.js --mock --workspace-preview --skip-welcome --no-open --host 127.0.0.1 --port 8099
```

In another terminal, run:

```powershell
node scripts/test-agent-workspace-preview.mts http://127.0.0.1:8099/
```

The check uses a fresh headless browser context, installed Edge on Windows or Playwright Chromium elsewhere, and the mock provider. It blocks external HTTP requests and operates on the browser-only sample workspace. It completes a mock conversation, retains a follow-up draft and an explicitly dirty untitled buffer across mode switches, edits and saves README.md, reloads the IDE, and opens the deferred Agents workbench. A report and screenshots are saved in `.build/agent-workspace-preview-smoke/<run>/`; failures retain their stage, report, and screenshot. Request interception disables the browser HTTP cache, so reload also exercises cold module loading. The script does not launch an installed editor, reuse a browser profile, or verify real provider authentication.

## Native build prerequisite

The pinned Node 24.22.1 archive was downloaded from nodejs.org, verified against its published SHA-256 manifest, and kept inside `.build/node-runtime`. Repository preinstall prepared Node and Electron 43.8.9 headers. The initial `MSB8040` blocker has been resolved by downloading the matching Microsoft Spectre archive, verifying its catalog hash, and using its libraries through build-local MSBuild properties. Fifteen native dependencies load in Electron, the client and extensions compile, and the native Agents window renders. See [Windows native development build](NATIVE_BUILD.md) for the isolated launcher, evidence, and remaining workflow limits.
